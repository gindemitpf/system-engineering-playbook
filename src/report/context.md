# Контекст и границы SoI

## 1.1. Цель системы

Целью системы является автоматизация первичного отбора кандидатов, повышение объективности оценки навыков и снижение рутинной нагрузки на HR-департамент за счёт интеллектуального анализа резюме, автоматизированного сопоставления с требованиями вакансий и генерации уточняющих вопросов для собеседований.

Система должна обеспечивать качественную обработку неструктурированных данных резюме, предотвращать предвзятость при первичном скрининге, учитывать специфику вакансий и предоставлять HR-специалистам актуальные данные для принятия решений о приглашении на интервью.

## 1.2. Внешние акторы

| Актор | Описание | Основной интерес |
| --- | --- | --- |
| Кандидат | Физическое лицо, откликающееся на вакансию | Быстро загрузить резюме, получить обратную связь, пройти первичную оценку |
| HR | Специалист по подбору персонала | Управлять вакансиями, видеть рейтинг кандидатов, получать подсказки для интервью |
| Руководитель отдела | Заказчик вакансии | Утверждать критерии отбора, просматривать отобранных кандидатов |
| Администратор | Ответственный за доступы и настройки AI | Контролировать работоспособность системы, доступы, мониторинг AI-моделей |

## 1.3. Внешние системы

| Внешняя система | Обоснование интеграции | Тип взаимодействия |
| --- | --- | --- |
| AI Model API (LLM) | Анализ текста, извлечение навыков и генерация вопросов требуют специализированных NLP-моделей — вынесение в API снижает зависимость от локальных ресурсов | REST API / gRPC |
| Cloud Storage | Хранение оригиналов резюме в различных форматах (PDF, DOCX) требует масштабируемого объектного хранилища | SDK / API |
| SSO / IdP | Централизованное управление учетными записями сотрудников организации | OAuth2/OIDC, JWT |
| Система мониторинга | Обеспечение наблюдаемости (логи, метрики) работы сервисов и API моделей | Metrics endpoint, logs |
| CRM / ATS | Интеграция с существующими системами компании для выгрузки результатов отбора | REST API / Webhooks |

## 1.4. Границы системы

### Внутри SoI

В состав системы входят:

* веб-интерфейс (Web UI) для HR и руководителей;
* сервис обработки резюме (Resume Service);
* сервис анализа и сопоставления (AI Analysis & Recommendation Service);
* API Gateway / Backend API;
* основная база данных (PostgreSQL);
* брокер сообщений (Message Broker) для асинхронной обработки;
* модуль генерации вопросов (LLM Integration Client);
* система журналирования и аудита.

### Вне SoI

За пределами системы находятся:

* корпоративный SSO / IdP;
* внешние AI-провайдеры (OpenAI, Anthropic, и др.);
* внешние системы хранения файлов (AWS S3 и аналоги);
* существующие корпоративные ATS/CRM-системы;
* внешние средства мониторинга;
* фактические собеседования и итоговые решения HR;
* политика компании по критериям найма.

## 1.6. Допущения и ограничения

1. Система ориентирована на работу с резюме в форматах PDF и DOCX.
2. AI-анализ является вспомогательным инструментом; финальное решение всегда принимает человек (Human-in-the-loop).
3. Система использует асинхронную обработку для тяжелых AI-операций.
4. Персональные данные кандидатов (PII) должны быть обезличены перед отправкой во внешние AI API.
5. При недоступности AI API система должна накапливать задачи в очереди (Retry policy).
6. Безопасность данных обеспечивается шифрованием "at rest" и "in transit".
7. Доступ к системе для HR и руководителей разграничен по ролям (RBAC).
8. Администратор обеспечивает мониторинг стоимости и эффективности использования внешних AI-моделей.
