Требования

3.1. Stakeholder requirements

IDЗаинтересованная сторонаТребованиеМетод проверки
SR-SH-1КандидатСистема должна позволять кандидату загрузить резюме в форматах PDF или DOCX.D, T
SR-SH-2КандидатСистема должна предоставлять кандидату статус обработки его резюме.D, T
SR-SH-3HRСистема должна автоматически извлекать ключевые навыки и опыт из текста резюме.D, I, T
SR-SH-4HRСистема должна рассчитывать процент соответствия кандидата требованиям конкретной вакансии (Match Score).D, T, A
SR-SH-5HRСистема должна генерировать список уточняющих вопросов для интервью на основе профиля кандидата.D, T
SR-SH-6HRСистема должна позволять фильтровать и сортировать кандидатов по рейтингу соответствия.D, T
SR-SH-7Руководитель отделаСистема должна предоставлять сводный отчет по качеству воронки кандидатов.D, A
SR-SH-8Системный администраторСистема должна поддерживать вход через корпоративный SSO и ролевую модель доступа (RBAC).I, T
SR-SH-9Системный администраторСистема должна обеспечивать полный аудит действий сотрудников при просмотре персональных данных.I, A, T
SR-SH-10ОрганизацияСистема должна обеспечивать обезличивание персональных данных при передаче во внешние AI-модели.I, A

3.2. System requirements

IDТребованиеМетод проверки
SR-SYS-1Система должна выполнять парсинг файлов резюме с использованием OCR и NLP-библиотек.T
SR-SYS-2Система должна нормализовать данные резюме в единый JSON-формат (навыки, опыт, образование).T, I
SR-SYS-3Система должна публиковать событие ResumeUploaded после успешного сохранения файла в хранилище.T
SR-SYS-4Система должна использовать асинхронную очередь для обработки анализа резюме через AI.I, T
SR-SYS-5Система должна обеспечивать идемпотентность при повторной загрузке одного и того же файла резюме тем же кандидатом.I, T
SR-SYS-6Система должна вычислять Match Score на основе семантического сходства векторов навыков.T, A
SR-SYS-7Система должна хранить историю изменений рейтинга кандидата для каждой вакансии.T
SR-SYS-8Система должна генерировать от 3 до 5 вопросов при запросе HR-специалиста.T
SR-SYS-9Система должна маскировать ФИО, телефон и email перед отправкой данных в AI API (PII Filtering).I, T
SR-SYS-10Система должна поддерживать версионирование вакансий и критериев отбора.T
SR-SYS-11Система должна предоставлять API для интеграции с внешними ATS через Webhooks.T, I
SR-SYS-12Система должна блокировать доступ к профилю кандидата, если у пользователя нет прав на вакансию.T, I
SR-SYS-13Система должна отправлять уведомления HR-специалисту о завершении анализа нового кандидата.T
SR-SYS-14Система должна автоматически переводить задачи в статус failed после 3 неудачных попыток вызова AI API.T, A
SR-SYS-15Система должна хранить логи доступа к данным в соответствии с политикой хранения (Retention Policy).I, A

3.3. NFR / требования качества

IDКатегорияТребованиеМетод проверки
NFR-1ПроизводительностьВремя парсинга резюме не должно превышать 10 секунд для файла до 5 МБ.T, A
NFR-2ПроизводительностьВремя получения Match Score не должно превышать 2 секунд при нагрузке 50 RPS.T, A
NFR-3ДоступностьДоступность API системы должна составлять не менее 99,9% в месяц.A, I
NFR-4МасштабируемостьСистема должна поддерживать обработку до 1000 резюме в час в пиковые периоды.T, A
NFR-5БезопасностьВсе персональные данные должны шифроваться алгоритмом AES-256 в базе данных.I
NFR-6ТочностьТочность извлечения ключевых навыков (F1-score) должна быть не ниже 85%.T, A
NFR-7НаблюдаемостьСистема должна логировать время отклика каждого вызова AI-модели.I, A
NFR-8СовместимостьПоддержка форматов: .pdf, .docx, .doc, .txt.T
NFR-9УстойчивостьПри недоступности AI-модели система должна сохранять запрос в очереди и retry-ить с exponential backoff.T, I
NFR-10UXПроцесс загрузки резюме для кандидата не должен превышать 2 кликов.D, A
