7.3. Тест-кейсы

TC-01. Загрузка резюме кандидатом

Цель: проверить успешную загрузку резюме в систему.

Предусловия: кандидат зарегистрирован в системе.

Данные: PDF-файл резюме размером менее 10 МБ.

Шаги:

  1. Выполнить вход в систему.
  2. Открыть страницу профиля кандидата.
  3. Выбрать файл резюме.
  4. Нажать кнопку загрузки.

Ожидаемый результат: резюме сохранено в Object Storage, метаданные созданы в базе данных, статус резюме установлен в uploaded.

Постусловия: запись Resume присутствует в PostgreSQL.

Покрываемые требования: SR-RES-1, SR-RES-2, SR-SYS-1.

TC-02. Создание задачи анализа резюме

Цель: проверить публикацию события после загрузки резюме.

Предусловия: резюме успешно загружено.

Данные: resumeId существующего резюме.

Шаги:

  1. Загрузить резюме.
  2. Проверить очередь сообщений.

Ожидаемый результат: в Message Broker опубликовано событие ResumeUploaded.

Постусловия: задача доступна для AI Analysis Service.

Покрываемые требования: SR-SYS-2, SR-SYS-3.

TC-03. Извлечение навыков AI-моделью

Цель: проверить корректность AI-анализа.

Предусловия: задача анализа находится в очереди.

Данные: резюме с навыками Python, PostgreSQL, Docker.

Шаги:

  1. Передать резюме в AI Analysis Service.
  2. Выполнить NLP-анализ.
  3. Проверить результаты.

Ожидаемый результат: система извлекает указанные навыки и сохраняет их с коэффициентом уверенности.

Постусловия: навыки сохранены в таблице Skill.

Покрываемые требования: SR-AI-1, SR-AI-2.

TC-04. Формирование рейтинга кандидатов

Цель: проверить расчёт Match Score.

Предусловия: существует вакансия и набор проанализированных кандидатов.

Данные: вакансия Backend Developer.

Шаги:

  1. Создать вакансию.
  2. Выполнить подбор кандидатов.
  3. Получить рейтинг кандидатов.

Ожидаемый результат: каждому кандидату присваивается Match Score от 0 до 100.

Постусловия: результаты сохранены в Application.

Покрываемые требования: SR-REC-1, SR-REC-2.

TC-05. Генерация вопросов для интервью

Цель: проверить создание Interview Script.

Предусловия: кандидат успешно сопоставлен с вакансией.

Данные: applicationId.

Шаги:

  1. Запустить генерацию интервью.
  2. Проверить полученный список вопросов.

Ожидаемый результат: сформирован набор релевантных вопросов по навыкам кандидата.

Постусловия: создан объект InterviewScript.

Покрываемые требования: SR-REC-3.

TC-06. Проверка интеграции с AI Provider

Цель: проверить взаимодействие с внешней AI-моделью.

Предусловия: настроен API-ключ провайдера.

Данные: текст резюме.

Шаги:

  1. Отправить запрос в AI Provider.
  2. Получить ответ модели.

Ожидаемый результат: ответ успешно обработан и сохранён.

Постусловия: результаты доступны Recommendation Service.

Покрываемые требования: SR-AI-3.

TC-07. Работа при недоступности AI Provider

Цель: проверить отказоустойчивость системы.

Предусловия: внешний AI Provider недоступен.

Данные: новое резюме.

Шаги:

  1. Имитировать отказ внешнего API.
  2. Загрузить резюме.
  3. Проверить статус обработки.

Ожидаемый результат: резюме сохраняется, задача переводится в Retry/DLQ, система продолжает работу.

Постусловия: данные кандидата не потеряны.

Покрываемые требования: NFR-5, NFR-6.

TC-08. Проверка авторизации через SSO

Цель: проверить интеграцию с корпоративной системой аутентификации.

Предусловия: пользователь существует в SSO.

Данные: JWT-токен сотрудника.

Шаги:

  1. Выполнить вход через SSO.
  2. Получить доступ к интерфейсу HR.

Ожидаемый результат: пользователь авторизован, роль определена корректно.

Постусловия: создана пользовательская сессия.

Покрываемые требования: SR-AUTH-1, SR-AUTH-2.

TC-09. Проверка разграничения ролей

Цель: проверить RBAC.

Предусловия: существуют роли Candidate, HR и Hiring Manager.

Данные: JWT-токены разных ролей.

Шаги:

  1. Выполнить вход под каждой ролью.
  2. Попытаться выполнить запрещённые действия.

Ожидаемый результат: недоступные операции возвращают ошибку 403 FORBIDDEN.

Постусловия: попытки доступа отражены в журнале аудита.

Покрываемые требования: SR-AUTH-3, NFR-4.

TC-10. Проверка журналирования действий

Цель: проверить аудит операций.

Предусловия: пользователь авторизован.

Данные: создание вакансии, просмотр резюме, изменение статуса кандидата.

Шаги:

  1. Выполнить указанные действия.
  2. Проверить AuditLog.

Ожидаемый результат: журнал содержит пользователя, время, действие и идентификатор объекта.

Постусловия: записи аудита доступны администраторам.

Покрываемые требования: SR-AUD-1, SR-AUD-2.

TC-11. Нагрузочная проверка поиска кандидатов

Цель: проверить производительность системы.

Предусловия: база содержит не менее 100 000 резюме.

Данные: 100 RPS на поиск кандидатов.

Шаги:

  1. Запустить нагрузочный тест.
  2. Измерить p95 времени ответа.

Ожидаемый результат: время ответа не превышает 1 секунду в p95.

Постусловия: сформирован отчёт нагрузочного тестирования.

Покрываемые требования: NFR-1, NFR-2.

TC-12. Проверка синхронизации с ATS/CRM

Цель: проверить обмен данными с корпоративной системой.

Предусловия: интеграция настроена.

Данные: кандидат со статусом Approved.

Шаги:

  1. Изменить статус кандидата.
  2. Выполнить синхронизацию.

Ожидаемый результат: ATS/CRM получает обновлённые данные кандидата.

Постусловия: данные синхронизированы между системами.

Покрываемые требования: SR-INT-1, SR-INT-2.
